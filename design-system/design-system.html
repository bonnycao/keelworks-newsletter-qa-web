06 / Testing specification

QA checks & implementation guidance

Automated tests must identify the component and its intended theme/background variant before treating differences as defects.

Implementation requirements

Light-mode email: inline critical styles, presentation tables with role="presentation", descriptive alt text for meaningful images, and text-based CTA labels. Dark mode is for the web presentation; email-client dark-mode overrides need separate testing.

Footer links and social destinations are reusable component references. The copyright year is dynamic, not a fixed QA value.

This reference is generated from accessible Figma metadata, local styles, and variables. Visual examples are illustrative, not pixel-perfect component exports. Use design-system.json as the rules source and review component-specific assertions before enabling them as failures.

07 / Automated QA

Links & Redirect Validation

Check every newsletter hyperlink, including story links, Donate, social media, browser link and footer links. Record original and final URLs, HTTP status, redirect chain and any defect. Redirects that reach a valid destination are not defects.

403, 429, bot protection and timeouts are inconclusive and require review. Email, telephone and in-page fragment links need separate validation.
